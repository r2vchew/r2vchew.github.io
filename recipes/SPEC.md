# Recipe Box — Specification

A personal recipe box web app. This document captures the requirements as
requested, the decisions made, and what was deliberately left out. The recipe
data shape is defined once in [`README.md`](README.md) (the single source of
truth for the schema); this spec references it rather than duplicating it.

- **Live at:** https://r2vchew.github.io/recipes/
- **Status:** Implemented and tested.

---

## 1. Purpose & philosophy

A private, offline-first place to store, search, display, and edit recipes —
used mainly from an Android phone's home screen.

The app is intentionally **"dumb"**: it stores, searches, displays, scales, and
edits recipes, and nothing more. Recipe *ingestion* (turning screenshots, links,
or messy text into structured recipes) happens **outside** the app via Claude —
see §7 and [`../RECIPE-INGESTION.md`](../RECIPE-INGESTION.md).

## 2. Architecture requirements

| Requirement | Decision |
| --- | --- |
| Progressive Web App (PWA) | Manifest + service worker; installable, runs offline |
| Hosted on GitHub Pages | Static files under `recipes/`, no build step |
| Add to Android home screen | `display: standalone`, app icons, theme colour |
| Single-page app | Hash-based routing (list / detail / editor views) |
| No backend server | Entirely client-side |
| Offline recipe database | **IndexedDB** (chosen over localStorage: async, no ~5 MB cap) |
| Works offline | Service worker caches the app shell |
| Canadian spelling in UI text | e.g. "colour", "favourite" — applied throughout |

## 3. Feature priorities (in the order requested)

1. **Search — the most-used feature; must be fast.**
   - Searches recipe **name + ingredients + notes** (also tags and source note).
   - Instant, as-you-type (all recipes held in memory; substring match).
   - Multi-word = AND (every word must appear somewhere); name matches rank first.
   - Accent-insensitive ("creme" finds "crème").

2. **Clean recipe display with serving scaling.**
   - Readable detail view: ingredients, steps, times, tags, source, notes.
   - A servings stepper rescales every numeric ingredient amount proportionally.
   - Amounts shown as **readable fractions** (1½, ⅔, ¼) rather than decimals
     where reasonable; deliberate decimals (1.1) are preserved.
   - A "scaled from N servings" note with a one-tap **Reset** appears when off
     the original yield.

3. **Easy editing of any recipe.**
   - Full editor for every field; add/remove ingredient and step rows.
   - Tag selection via tappable chips; unit autocomplete.
   - Delete (with confirmation) lives in the editor.

4. **Lightweight tag filtering.**
   - Horizontally scrollable filter chips on the list; multiple tags combine as
     AND. Deliberately simple — search is the priority.

## 4. Recipe schema

Defined authoritatively in [`README.md`](README.md). Summary of the shape:
`id`, `name`, `source {type, url, note}`, `servings`, `time {prep_minutes,
cook_minutes}`, `ingredients [{amount, unit, item, prep}]`, `steps[]`, `tags[]`,
`notes`, `date_added`.

**Key rules:**
- **Fuzzy amounts** ("a good glug", "2–3 cloves"): `amount` is `null` and the
  fuzzy wording goes in `prep`. Null amounts display as-is and **do not scale**.
- Everything with a real numeric `amount` scales.
- `id` and `date_added` are generated by the app on import when absent (a stable
  `id` in an import file means a re-import **updates** rather than duplicates).
- `source.url` is restricted to http/https/mailto before being shown as a link.

## 5. Tags (controlled list)

A fixed list, applied in the editor and as filters; search matters more, so this
is kept simple and not over-engineered:

> breakfast, lunch, dinner, snack, dessert, side, sauce/condiment, beef, chicken,
> pork, fish/seafood, vegetarian, beans/legumes, one-pot, grill/BBQ, slow-cook,
> no-cook, baking, soup/stew, weeknight, weekend/project, crowd/entertaining,
> kid-approved

## 6. Import & export

- **Import** accepts JSON matching the schema as either a single object, an array,
  or `{ "recipes": [...] }`. Two ways to provide it:
  - **Paste** JSON directly into the Import dialog (best on a phone, straight from
    a Claude ingestion session).
  - **Choose a file** (a `.json` dropped in to bulk-add).
  - Recipes **merge by `id`**: new ids are added, matching ids overwritten;
    invalid entries are skipped and counted.
- **Export** downloads all recipes as a single timestamped JSON file — the backup
  for the separate Claude ingestion workflow and the only off-device copy.

## 7. Recipe ingestion (separate from the app)

Documented fully in [`../RECIPE-INGESTION.md`](../RECIPE-INGESTION.md) and wired as
the `recipe-ingestion` Claude skill. A separate Claude session converts source
material into schema JSON, which is then imported (§6). Three paths:

| Path | Input | `source.type` | Notes |
| --- | --- | --- | --- |
| Screenshots | Images in a Google Drive folder (pointed at or attached) | `screenshot` | Claude reads the images and extracts each recipe |
| Web links | A recipe URL | `link` | Fetch page directly first; prefer embedded JSON-LD `Recipe` data; fall back only if blocked. URL stored |
| Freeform / manual | Pasted or rough text | `manual` | Claude structures it into the schema |

Ingestion rules: fuzzy amounts → `null` + `prep`; tags only from the controlled
list; **never fabricate** missing times/servings (leave `null`); generate a UUID
`id` per recipe; omit `date_added` (the app stamps it).

## 8. Data durability

The recipe data lives only on-device, so:
- The app requests **persistent storage** (`navigator.storage.persist()`) on load
  so the browser won't evict the database under storage pressure.
- **Export is the backup of record.** Clearing site data or uninstalling the app
  wipes the box; regular exports are the safety net.

## 9. Out of scope (by design)

- No backend, accounts, or cloud sync.
- No in-app ingestion / OCR / link-scraping — that is Claude's job (§7).
- **Android Share Target** (share a URL/screenshot straight into the app as a
  "to-ingest" queue) — *considered and deferred*; a candidate for a future round.
